## Google Chrome

Endpoint `POST /chrome/session` · connect with Playwright `chromium` 1.60 · [docs page](https://cdpfleet.com/docs/browsers/chrome)

The real Google Chrome, with stable, beta and dev channels and recent previous majors. The best choice when a site must see genuine Chrome.

| Option | Type | Default | What it does |
|---|---|---|---|
| `proxy` | `string \| object \| array` | the free Community proxy | Upstream proxy for the browser. **Use it for:** Every session that needs a particular exit: your own proxy for the IP and country you choose, a list as a pool to spread requests across IPs, or a `cdpfleet-resi` token for residential IPs billed per GB. Optional: without a proxy (and without `vpn`) the free Community proxy is used — shared, slower and capped (`503 community_capacity_full` when busy), so bring your own or use the residential proxy for work that matters. Sessions never browse from our servers' own IPs. An unparseable proxy returns 400. |
| `proxy_rules` | `array` | none | Send specific destination hosts through specific proxies. **Use it for:** Scrapers that want an expensive exit only where it matters: residential for the target site, a cheaper proxy for images, CDNs and APIs, or a different country per host. Needs `proxy` to be set as the default route. Rules route through a proxy only; routing a host with no proxy (direct from our servers) is not available. The first matching rule wins — keep rules from overlapping so traffic is attributed to the right one. |
| `inactivity_timeout` | `number \| string` | 120s | End the session after this long with no traffic on its WebSocket. **Use it for:** Freeing the thread quickly when a script dies (short), or giving a person or a slow step time to think (long), up to your plan's cap. Up to 10 minutes on shared threads, 5 on Community and 24 h on dedicated; a longer value is cut to your plan's maximum. Idle minutes are billed like any others. A slow page load through a proxy can produce no traffic for a while, so keep it at 60 s or more. Never longer than the session's overall timeout. |
| `overall_timeout` | `number \| string` | your plan's maximum session length (24 h) | Hard cap on the session's total lifetime, regardless of activity. **Use it for:** A hard time budget per job, so a stuck loop can't hold a thread for hours: batch scrapers and agents with a deadline. |
| `vpn_tunnel` | `boolean` | false | VPN Tunnel: UDP/WebRTC full support — all of the browser's traffic, UDP included, goes through the residential exit. **Use it for:** Work that needs WebRTC or HTTP/3 to look like a home connection, such as video calls or sites that compare the WebRTC address with the page's IP, on a sticky residential exit. Needs the default `proxy` to be a `cdpfleet-resi` token on Tier 1 or Tier 2 (no `-tier-N` is Tier 1), or, on dedicated plans, your own proxy too (UDP then works if your SOCKS5 proxy relays it; not billed); anything else — Tier 3/4, a pool, your own proxy on other plans — returns `400 tunnel_not_available`. `proxy_rules` still route page traffic by host, but UDP (WebRTC, HTTP/3) can leave through a rule's proxy instead of the default, because a UDP flow carries no host for the rules to match: for WebRTC that matches the page's exit, don't combine the tunnel with `proxy_rules`. A live swap must keep a Tier 1/2 token. Sticky sessions (`-session-…`) work best: with a rotating exit, WebRTC and HTTP/3 may show a different residential IP than the page. Adds about 0.1 s to the launch. |
| `vpn` | `string \| object` | none | Own network (dedicated plans): send all of the browser's traffic through your own VPN instead of a proxy. **Use it for:** Dedicated-plan users who already run their own VPN (WireGuard, AmneziaWG, OpenVPN, sing-box): the whole browser, UDP included, leaves through it, so pages and WebRTC show the VPN's address. Dedicated plans only (`403 vpn_requires_dedicated`). Not with `proxy`, `proxy_rules` or a live swap (`400 vpn_not_available`). Config, username and password together up to 64 KB (`400 invalid_vpn_config`). A server that doesn't answer or refuses the credentials returns `400 vpn_connect_failed`. Not billed. Keep the config out of your code: read it from a file or an environment variable. See [Own network](https://cdpfleet.com/docs/proxies#own-network). |
| `headless` | `boolean \| "new" \| "shell"` | false (headful, on a virtual display) | Run without a display. **Use it for:** Bulk scraping and tests where nobody watches: lower memory and faster launches. Leave it headful (the default) when a site checks for headless tells, or when you want a recording or live view without extra options. |
| `channel` | `"stable" \| "beta" \| "dev" \| "developer"` | stable | Release channel of the browser build. **Use it for:** QA teams checking a site against the next browser release before users get it (beta, dev), and scrapers that want to see a change coming. Opera calls its dev channel `developer`. `browser.version()` reports the underlying Chromium version; for Brave, Opera, Whale and Yandex that differs from the product version listed here. |
| `version` | `string` | none (latest stable) | Pin an older major version. **Use it for:** Reproducing a bug on an older browser, keeping a scraper on a known-good build while you test the new one, or matching a customer's browser. Previous majors rotate out automatically: Chrome keeps its two most recent previous majors and drops the oldest within about a day of a new stable release; Camoufox keeps recent majors plus long-term ones. Read the live list rather than hard-coding a number. Send either `version` or a pre-release `channel`, not both: together they return `400` (`channel: "stable"` with a `version` is fine). |
| `cdp` | `boolean` | false | Also expose a Chrome DevTools Protocol endpoint (cdpUrl). **Use it for:** Puppeteer users and tools that speak raw CDP (Lighthouse, custom DevTools clients), or connecting with Playwright's connectOverCDP to reach Chromium-only features like network throttling and performance traces. Same session, proxy and limits. You can connect to `wsUrl` and `cdpUrl` at once, but closing either ends the session. Not on Patchright and Rebrowser (their stealth lives in the Playwright layer CDP bypasses), Whale, Camoufox, Firefox or WebKit. |
| `screencast` | `boolean` | false | Stream the page to your code (Playwright page.screencast). **Use it for:** Watching or recording a headless page from your own code as a stream of JPEG frames, for debugging dashboards or human review, without a full live view. View-only and only for the client that drives the page. With `"cdp": true`, use CDP `Page.startScreencast` instead. To watch from somewhere else — or take control — see `live_view` and [Live view](https://cdpfleet.com/docs/live-view). |
| `live_view` | `boolean` | false (headful sessions are always watchable) | Make a headless session watchable and controllable from outside. **Use it for:** A person watching or taking over the session in the browser (a login, a 2FA step, a check that needs a human), or recording a headless session. Headless Chromium-based browsers only (Camoufox, Firefox and WebKit are watchable when headful, their default). Doesn't give your code CDP access — add `"cdp": true` for that. The session is also [recorded](https://cdpfleet.com/docs/recordings) unless you add `"record": false`. See [Live view](https://cdpfleet.com/docs/live-view). |
| `screen_size` | `"WxH" \| { width, height }` | the server's display (1280×720 window) | Resolution of the session's own display (headful only). **Use it for:** Responsive and visual tests at a given resolution, and personas that need a common desktop or laptop screen instead of the server default. Headful sessions only — a headless launch with `screen_size` returns 400. Playwright contexts report a screen equal to their viewport (1280×720) unless you open them with `viewport: null` (Python `no_viewport=True`, Java `setViewportSize(null)`, C# `ViewportSize = ViewportSize.NoViewport`, Go `NoViewport: playwright.Bool(true)`); Camoufox always reports the display — the nearest real-world screen size no larger than it (exact for common sizes such as 1366×768 or 1920×1080); with `"os": "macos"` use 1440×900 or larger, since no Mac screen is smaller (400 otherwise). |
| `keep_alive` | `boolean` | false | Keep the session when your client disconnects (dedicated threads only). **Use it for:** Agents and step-by-step workflows that disconnect between steps, and code that may lose its connection, without losing the logged-in browser. Not on Rebrowser. Dedicated threads only (`403 keep_alive_requires_dedicated` on shared plans). The session is billed while it's alive, attached or not — and `browser.close()` only disconnects: the session ends after `inactivity_timeout` without a client, or at once with `DELETE /v1/me/threads/{sessionId}` (or End in the dashboard). Set `inactivity_timeout` to how long it may wait for you. |
| `start_url` | `string (http/https URL)` | none | Open this page at launch so the session can be driven in live view with no client connected. **Use it for:** A person logs in or passes a check by hand in live view first; then your code connects and carries on in the same page. http or https, at most 2,048 characters (`400 invalid_start_url`). Headless needs `"live_view": true` on a Chromium-based browser; Firefox, Camoufox and WebKit only headful (`400 start_url_not_viewable`). Without `keep_alive`, a client that connects and then disconnects ends the session. See [Launch interactive](https://cdpfleet.com/docs/live-view#launch-interactive). |
| `profile` | `string \| object` | none | Restore a saved browser profile and save it again when the session ends. **Use it for:** Staying logged in between sessions: log in once, then every later launch starts with the same cookies and storage (and, on Camoufox, the same device). Every browser except Whale and Rebrowser. Keeps cookies (session cookies too), localStorage and IndexedDB; not sessionStorage. 20 profiles per shared thread and 30 per dedicated thread (at least 100), 50 MB each; list and delete with `/v1/me/profiles`. |
| `record` | `boolean` | true (when recording applies) | Opt this session out of recording with false. **Use it for:** Keeping a video of each run for debugging, QA evidence or audits. Set `false` when you don't need it, to keep the recording quota for runs that matter. Recording applies to headful sessions and to headless ones launched with `"cdp": true` or `"live_view": true`, at 480p (720p or 1080p on a recording plan). Recordings appear on the dashboard's Sessions page. See [Session recording](https://cdpfleet.com/docs/recordings). |
